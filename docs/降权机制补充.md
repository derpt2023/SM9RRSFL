# SM9-RRS-FL 疑似恶意节点动态降权机制补充

建议插入位置：方案文档第 `4.3.3 投毒检测` 小节中，放在原“过程3. 基于3σ准则的拦截与问责触发机制”之后、`4.3.4 恶意节点追溯` 之前。建议新增为：

`过程4. 疑似恶意节点动态降权与确认问责机制`

## 补充正文

考虑到异常检测算法存在误报风险，若聚合服务器在单轮检测到异常后立即触发审计并将客户端从联邦学习网络中剔除，可能在高恶意比例或非独立同分布场景下导致诚实节点被误伤，进而破坏全局模型的持续收敛能力。为此，本文借鉴文献 [13] 的动态权重惩罚思想，将“单次异常即剔除”改为“疑似异常先降权、连续异常再问责”的渐进式处理策略。

设第 `r` 轮参与聚合的客户端集合为 `A^(r)`，客户端 `C_π` 上传的模型更新为 `G_π^(r)`，其可链接匿名标签为 `Tag_π`。聚合服务器基于纵向 SVD 检测算法得到异常判定变量：

```text
R_π^(r) =
  1, 若 Tag_π 对应的节点在第 r 轮被判定为疑似异常；
  0, 否则。
```

为每个可链接标签 `Tag_π` 维护聚合权重 `w_π^(r)`，初始状态下：

```text
w_π^(0) = 1 / |A^(0)|,    Σ_π w_π^(0) = 1。
```

设 `ρ ∈ (0,1)` 为疑似节点惩罚因子，`γ > 1` 为权重恢复因子。对第 `r` 轮检测结果，先计算未归一化权重：

```text
                 ρ · w_π^(r-1),                              若 R_π^(r) = 1；
w~_π^(r) =       min{γ · w_π^(r-1), 1 / |A^(r)|},             若 R_π^(r) = 0 且 w_π^(r-1) < 1 / |A^(r)|；
                 w_π^(r-1),                                  其他情况。
```

随后执行归一化，使所有未被确认剔除的客户端权重之和保持为 1：

```text
w_π^(r) = w~_π^(r) / Σ_{C_i ∈ A^(r)} w~_i^(r)。
```

因此，第 `r` 轮全局模型更新不再采用简单平均，而是采用动态加权聚合：

```text
ΔG^(r) = Σ_{C_i ∈ A^(r)} w_i^(r) · G_i^(r),

G^(r+1) = G^(r) + ΔG^(r)。
```

与此同时，为每个可链接标签维护连续异常计数：

```text
Count_π^(r) =
  Count_π^(r-1) + 1, 若 R_π^(r) = 1；
  0,                  若 R_π^(r) = 0。
```

当 `Count_π^(r) < C_tol` 时，聚合服务器仅认为该客户端为疑似异常节点，不立即撤销其匿名身份，也不将其从联邦学习系统中剔除，只降低其本轮及后续聚合贡献。当 `Count_π^(r) ≥ C_tol` 时，说明该客户端在连续多轮中表现出稳定异常轨迹。此时 AS 按最新版 Word 方案立即令该标签的触发轮权重为 0、拒绝该梯度参与本轮聚合，同时将触发轮数据包、模型更新和异常轨迹组成完整证据 `E_π`，提交给 Auditor/D-KGC 并触发 `4.3.4` 节中的门限身份追踪流程。只有追踪结果与任务标签一致且门限 Schnorr 证书验证成功后，才永久撤销该身份并加入黑名单：

```text
若 Count_π^(r) ≥ C_tol，则先令 w_π^(r) = 0 并请求 Trace(E_π)；
τ_trace = (R_trace, z_trace)；
e_trace = H2("SM9-RRS-FL/threshold-schnorr/v2" || M_trace || R_trace,N)；
仅当 [z_trace]P2 = R_trace + [e_trace]TPK 时，
执行 Revoke(ID_π) 并更新任务环。
```

这里的 `τ_trace` 是由不少于 `t` 个 D-KGC 节点联合生成的门限 Schnorr 证书，而不是可被线性缩放的单群元证书。`M_trace` 同时绑定触发证据摘要、追踪身份、任务标签、`RID` 和固定字符串 `"trace"`；任一字段变化都会使验证失败。

若追踪、标签一致性或证书验证因临时故障未完成，本次结果不得形成永久撤销。AS 保留完整、不可变的待审计证据及其摘要，继续拒绝该触发轮梯度，并暂停任务终结；系统重启后必须先用同一份证据完成重试。待审计项未归档前不得销毁 `h_t` 和 `κ_t`。若所有本轮更新均达到 `C_tol`，有效聚合权重和可以为 0，此时本轮全局更新取零向量，而不是绕过拒绝规则重新归一化这些触发项。

该机制保留了本文方案的可追责能力，同时避免单轮误报直接造成永久身份撤销。在高恶意节点比例与非独立同分布数据场景下，动态降权可缓冲检测误差对全局模型的冲击；未达到 `C_tol` 且后续恢复正常的标签仍可逐步恢复聚合权重。

## 与原流程的衔接

原 `4.3.3` 中“检测到异常后立即拒绝梯度并提交审计”的描述，建议改为：

```text
一旦触发任一异常判定逻辑，AS 不立即将该客户端从系统中剔除，而是将其标记为疑似异常节点，并按照动态降权规则降低其聚合权重。若同一任务标签的连续异常计数达到 C_tol，AS 才将完整证据提交至 Auditor/D-KGC。Auditor 复核环签名第一验证等式，D-KGC 完成门限身份追踪和任务标签一致性检查并返回追踪证书；AS 验证证书后才执行最终剔除。
```

`4.3.4 恶意节点追溯` 的触发条件为“同一任务标签连续异常达到阈值 `C_tol`”，撤销条件为“追踪等式、标签一致性和门限 Schnorr 证书均验证通过”。

代码中的 D-KGC 是单进程份额域协议模型：Shamir/Feldman、交叉项刷新、随机盲化求逆和门限 Schnorr 关系会真实执行，且环建立与追踪路径不重构完整秘密。追踪请求还必须包含不少于 `t` 个节点分别对 `TaskID、RID、H5(E_π)` 和一次性会话标识生成的有效 Schnorr 批准；节点编号不能代替批准，已使用会话不能重放。论文中的 Paillier 密文报文及跨节点认证信道不在本实验仓库中部署。该区别不改变上述降权和撤销状态机，但生产实现仍必须使用相互隔离、经认证通信的 D-KGC 节点。
