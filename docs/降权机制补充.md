# SM9-RRS-FL 疑似恶意节点动态降权机制补充

建议插入位置：方案文档第 `4.3.3 投毒检测` 小节中，放在原“过程3. 基于3σ准则的拦截与问责触发机制”之后、`4.3.4 恶意节点追溯` 之前。建议新增为：

`过程4. 疑似恶意节点动态降权与确认问责机制`

## 补充正文

考虑到异常检测算法存在误报风险，若聚合服务器在单轮检测到异常后立即触发审计并将客户端从联邦学习网络中剔除，可能在高恶意比例或非独立同分布场景下导致诚实节点被误伤，进而破坏全局模型的持续收敛能力。为此，本文借鉴文献 [13] 的动态权重惩罚思想，将“单次异常即剔除”改为“疑似异常先降权、连续异常再问责”的渐进式处理策略。

设第 `r` 轮参与聚合的客户端集合为 `A_r`，客户端 `C_i` 上传的模型更新为 `Δ_i^(r)`，其可链接匿名标签为 `Tag_i`。聚合服务器基于纵向 SVD 检测算法得到异常判定变量：

```text
R_i^(r) =
  1, 若 C_i 在第 r 轮被判定为疑似异常；
  0, 否则。
```

为每个可链接标签 `Tag_i` 维护聚合权重 `ω_i^(r)`，初始状态下：

```text
ω_i^(0) = 1 / |A_0|,    Σ_i ω_i^(0) = 1。
```

设 `α ∈ (0,1)` 为疑似节点惩罚因子，`γ > 1` 为权重恢复因子。对第 `r` 轮检测结果，先计算未归一化权重：

```text
                 α · ω_i^(r-1),                         若 R_i^(r) = 1；
ω~_i^(r) =       min{γ · ω_i^(r-1), 1 / |A_r|},          若 R_i^(r) = 0 且 ω_i^(r-1) < 1 / |A_r|；
                 ω_i^(r-1),                              其他情况。
```

随后执行归一化，使所有未被确认剔除的客户端权重之和保持为 1：

```text
ω_i^(r) = ω~_i^(r) / Σ_{C_j ∈ A_r} ω~_j^(r)。
```

因此，第 `r` 轮全局模型更新不再采用简单平均，而是采用动态加权聚合：

```text
ΔG^(r) = Σ_{C_i ∈ A_r} ω_i^(r) · Δ_i^(r),

G^(r+1) = G^(r) + ΔG^(r)。
```

与此同时，为每个可链接标签维护连续异常计数：

```text
q_i^(r) =
  q_i^(r-1) + 1, 若 R_i^(r) = 1；
  0,             若 R_i^(r) = 0。
```

当 `q_i^(r) < L` 时，聚合服务器仅认为该客户端为疑似异常节点，不立即撤销其匿名身份，也不将其从联邦学习系统中剔除，只降低其本轮及后续聚合贡献。当 `q_i^(r) ≥ L` 时，说明该客户端在连续多轮中表现出稳定异常轨迹，聚合服务器才将其数据包、异常证据及对应陷门提交给审计中心，触发 `4.3.4` 节中的恶意节点追溯流程。审计成功后，将该客户端权重置为 0，并将其加入黑名单：

```text
若 q_i^(r) ≥ L，则触发 Revoke(Tag_i)，并令 ω_i^(r) = 0。
```

该机制保留了本文方案的可追责能力，同时避免单轮误报造成诚实节点被永久剔除。在高恶意节点比例与非独立同分布数据场景下，动态降权可缓冲检测误差对全局模型的冲击，使疑似节点影响被及时抑制，而诚实节点在后续轮次表现正常时仍可恢复聚合权重。

## 与原流程的衔接

原 `4.3.3` 中“检测到异常后立即拒绝梯度并提交审计”的描述，建议改为：

```text
一旦触发任一异常判定逻辑，AS 不立即将该客户端从系统中剔除，而是将其标记为疑似异常节点，并按照动态降权规则降低其聚合权重。若该客户端在连续 L 轮中均被判定为异常，AS 才将其数据包、异常轨迹证据和可撤销陷门提交至 Auditor，触发身份追溯与最终剔除。
```

原 `4.3.4 恶意节点追溯` 可保持主体不变，但触发条件应由“单轮检测异常”改为“连续异常达到阈值 `L` 后触发”。
