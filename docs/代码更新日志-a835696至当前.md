## 2. VERT 公平对比与论文核心校正

### 2.1 无先验默认模式

旧版 `--vert-top-k 0` 会读取 `ExperimentConfig.malicious_ratio`，再根据当轮活跃客户端数推导 Top-k，属于已知恶意比例的 `VERT-known-f`。当前默认逻辑为：

- `VERTDefense.malicious_ratio_prior=None`；
- `--vert-top-k 0` 对本轮余弦相似度执行一维 K-means，`K=2`；
- 保留中心值较高的簇；
- 分数完全相同或无法形成两个有效簇时，保留全部活跃客户端；
- 该路径不读取实验中的真实恶意比例。

### 2.2 已知比例复现接口

新增：

```text
--vert-use-ratio-prior
```

开启后，每个实验配置自动使用它自己的恶意比例 `r` 和当轮活跃数 `n`：

```text
r = 0: k = n
r > 0: k = max(1, ceil((1-r)n) - 1)
```

该参数可与多个 `--ratios` 和 `--client-counts` 直接组合，无需逐项手算 `k`。正整数 `--vert-top-k` 仍用于固定 `k` 复现，不能与比例先验开关同时使用。

无先验、已知比例和固定 `k` 三种模式共用同一套投影、历史、预测器训练、余弦评分与等权 FedAvg 逻辑，仅在获得相似度分数后分叉。

### 2.3 共享核心校正

按 VERT 论文和公开实现校正：

- 前两轮等权 FedAvg 建立历史，第 3 轮开始预测和筛选；
- 冻结随机线性投影器，投影输出不再施加 Softmax；
- 每个全局轮次重新初始化共享三层预测器和两个逐元素集成系数；
- 预测器仅前两层使用 ReLU，最后一层保持线性输出；
- 集成系数由全 `1` 模板初始化；
- Adam 默认学习率由 `0.001` 校正为论文值 `0.01`；
- 入选客户端使用 `1/k` 等权 FedAvg，不再按余弦分数加权；
- 未入选或历史缺失的客户端仍用本轮全局更新替换历史。

## 3. Ours 的 `Count` 整数半衰减

`SuspicionWeightManager` 当前状态转移为：

```text
双指标共同越界：Count <- Count + 1
两项均未越界：  Count <- floor(Count / 2)
仅单指标越界：  Count 保持不变，同时执行动态降权
```

`Count` 继续使用历史属性名 `consecutive_suspicions` 以减少无关检查点改动，但语义已改为非负整数异常证据。例如 `1→0`、`3→1`、`5→2`，追踪触发条件仍为 `Count >= C_tol`。

## 4. JSON 配置启动器

新增：

```text
configs/experiment.json
sm9rrsfl/config_runner.py
run_experiments_from_config.py
tests/test_config_runner.py
```

特性：

- `schema_version=1` 的 JSON 包装；
- 参数名与原 `sm9rrsfl.experiments` 长参数一一对应；
- 支持标量、列表和布尔参数；
- 额外支持 `early_stop`、`visualizations`、`progress`、`resume` 正向布尔别名；
- 未知键、错误 schema、空列表和原 CLI 不允许的组合会在训练前拒绝；
- `--dry-run` 输出最终命令与解析后参数；
- 根目录启动文件会优先重启到项目 `.venv` 解释器；
- 配置入口最终仍调用权威的 `experiments.main(argv)`，不维护第二套实验逻辑。

使用方式：

```bash
./run_experiments_from_config.py

python -m sm9rrsfl.config_runner \
  --config configs/experiment.json

python -m sm9rrsfl.config_runner \
  --config configs/experiment.json \
  --dry-run
```

当前示例配置已填入最近一次 MNIST 六方案实验的数据、训练、攻击、VERT、FedREDefense 和 SM9-RRS 参数，并使用 `jobs: auto`。该配置为用户可编辑运行配置；测试只验证它能被通用加载器处理，不再把配置内容锁定为 synthetic smoke 实验。

## 5. 实验网格并行调度

旧版并行不明显的两个原因是 `--jobs` 默认为 `1`，且 CUDA/MPS 被无条件限制为单配置。当前逻辑：

- `--jobs` 默认为 `auto`；
- CPU/NumPy 和 torch CPU 使用 `ProcessPoolExecutor`；
- 每个 worker 从实验网格队列中领取独立配置；
- 进程池因 semaphore/环境权限不可用时，只对剩余配置回退线程池；
- CUDA/MPS 使用同一进程内的 `ThreadPoolExecutor`，避免 accelerator fork 初始化问题；
- 单加速器的 `auto` 默认最多同时调度 2 个配置，显式 `--jobs N` 可提高；
- 加速器数据集常驻张量缓存增加互斥锁，避免并发首次上传重复创建设备张量；
- 启动时输出 `experiment_jobs=N` 和 `experiment_executor=serial|process|thread`。

并行粒度是实验网格中的独立配置，而不是将单个配置的一轮训练无限拆分。单块 GPU/MPS 上的实际加速比受设备算子串行化和显存/统一内存压力限制。

## 6. 实时进度和 ETA

`ProgressReporter` 增加守护刷新线程、互斥锁和停止事件：

- 交互式 TTY 默认每 1 秒重绘进度；
- 无新配置完成时，`elapsed` 仍实时变化；
- 第一个配置完成前显示 `eta=estimating`；
- 建立本次运行的吞吐量估计后，ETA 每秒倒计时；
- 非 TTY 日志只在状态事件时输出，避免重定向文件每秒增加一行。
