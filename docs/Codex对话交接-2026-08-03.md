## 2. Ours 第 49/50 轮异常

实验配置为 `100` 个客户端、Dirichlet `alpha=0.5`、`60%` 恶意节点、`50` 轮、`attack_boost=20`、惩罚因子 `0.2`、恢复因子 `5.0`。

关键指标：

| 轮次 | Ours 准确率 | ASR | 恶意总聚合权重 | `client-56` 聚合权重 | 判定 |
|---:|---:|---:|---:|---:|---|
| 48 | 0.8842 | 0.109375 | 0.004791 | 0.004791 | 双指标异常 |
| 49 | 0.6777 | 0.789063 | 0.035649 | 0.035649 | 正常接受 |
| 50 | 0.8737 | 0.117188 | 0.010385 | 0.010385 | 双指标异常 |

第 49 轮几乎全部恶意聚合权重都来自仍存活的 `client-56`。该节点第 48 轮被双指标判异常，但异常特征仍成为下一轮的 `last_observed`；第 49 轮持续攻击更新相对上一轮攻击更新非常相似，`z_sigma=1.6163`、`z_direction=2.4990`，均未超过阈值 `3.0`，于是：

- `Count` 从 `1` 清零；
- 权重按恢复因子 `5.0` 从 `0.0047908` 恢复到活跃客户端均匀权重上限 `1/47=0.0212766`；
- 当轮大量其他节点被惩罚，归一化后 `client-56` 实际占 `3.5649%`；
- 配合 `boost=20` 的目标攻击，ASR 升至 `78.91%`，准确率降至 `67.77%`。

第 50 轮该节点的 `z_sigma=3.5323`、`z_direction=12.5841`，重新触发双指标异常，权重下降；诚实节点取得 `98.96%` 聚合权重，所以准确率恢复到 `87.37%`，接近同轮 VERT 的 `88.40%`。恢复不是因为攻击停止，也不是因为 `client-56` 被撤销；该节点第 50 轮 `Count` 仅回到 `1`。

在攻击开始后的第 7–50 轮，恶意总聚合权重与准确率的皮尔逊相关系数为 `-0.968`，与 ASR 的相关系数为 `0.802`，与上述权重驱动解释一致。

上述分析完成时尚未修改 Ours；随后已按用户要求加入 `Count` 半衰减，见第 7 节。

## 3. VERT 先验审计与最终修改

旧实现存在明确先验：

```text
ExperimentConfig.malicious_ratio
  -> VERTDefense(malicious_ratio=...)
  -> ceil((1-ratio) * active_count) - 1
  -> 每轮 Top-k
```

因此旧实验目录 `outputs/mnist_6fangan_teacher5` 中 `vert_top_k=0` 的 VERT 结果属于 `VERT-known-f`，不能作为已经去除先验后的公平结果继续使用。

曾经实现过一版“显著相邻分数间隙”的无先验切分，但该规则不是论文 VERT 的无先验方案，而且共享核心仍有 Softmax、相似度加权聚合和跨轮保留预测器等偏差。该中间版本只存在于 schema `7`，不再是当前最终语义。

对照论文第 IV-C、算法 1、第 VI-C3 节及论文公开仓库 `https://github.com/mylab426/VERT` 后，当前 schema `8` 已改为：

- 默认模式下，`VERTDefense.malicious_ratio_prior=None`，`fl.py` 不把实验恶意比例传入 VERT；
- `--vert-top-k 0` 对当轮余弦相似度执行一维 K-means（$K=2$），选择中心值较高的簇；分数相同等退化情形保留全部客户端；
- `--vert-use-ratio-prior` 只有在最终选择阶段才使用当前配置的恶意比例，并按项目旧版自动公式计算 $k$；
- 正整数 `--vert-top-k` 仍表示固定 $k$，与比例先验开关互斥；
- 三种模式在进入选择器前共用同一个 `_effective_top_k` 上游评分结果，测试已验证在相同种子、历史和当前更新下，三种模式的 `scores` 字典完全相同；多轮后因上一轮选择不同而造成的历史不同属于选择策略的自然后果，不是额外读取先验。

共享 VERT 核心也已按论文与公开实现校正：

- 前两轮等权 FedAvg 建立历史，第 3 轮开始预测筛选；
- 线性投影器冻结，不在预测器训练中更新；投影输出直接用于训练和余弦评分，不施加 Softmax；
- 每个全局轮次重新初始化一个共享三层预测器和两个逐元素集成系数，按客户端顺序继续训练，并在每个客户端训练后立即评分；公开代码的预测器只在前两层后使用 ReLU，最后一层为线性输出；
- 集成系数按公开实现从全 `1` 模板开始，预测器和系数使用 Adam，默认学习率由 `0.001` 改为论文的 `0.01`，预测 epochs 仍为 `5`、历史窗口仍为 `10`；
- 入选客户端不再按余弦分数加权，而是按算法 1 和公开 `vert_fedavg` 的 `1/k` 等权 FedAvg；
- 未入选或历史缺失客户端仍以该轮全局更新替换历史。

多比例、多客户端数量的有先验复现实验可直接在原命令后增加：

```text
--vert-use-ratio-prior
```

每项配置会自动使用自己的 $r$ 和当轮活跃客户端数 $n$：$r=0$ 时保留全部客户端，否则 $k=max(1, ceil((1-r)n)-1)$，无需逐项手算 `--vert-top-k`。这是为了复现本项目旧版已知比例 VERT 而保留的便利接口；论文主实验实际写死了不同场景的 $k=[60,50,15,8]$，需要精确复现论文表格时仍应传正整数 `--vert-top-k`。

实验检查点 schema 最终已从 `3` 升到 `8`：版本 `4` 对应早期 VERT 去先验，版本 `5` 加入浮点 `Count` 半衰减，版本 `6` 改为向下取整的整数半衰减，版本 `7` 加入显式 VERT 比例先验接口，版本 `8` 对应本次 K-means 无先验选择和共享核心校正。旧断点、完成快照及旧 VERT 曲线都不应与 schema `8` 混续或直接比较；重新实验应使用新输出目录，或明确 `--no-resume`。

## 7. Ours 的 Count 半衰减更新

用户随后要求：疑似恶意节点在一轮被认为正常时，不再把 `Count` 直接清零，而是更新为原值的一半；若 `Count` 为奇数，则向下取整。

当前精确定义：

```text
双指标共同越界：Count <- Count + 1
两项均未越界：  Count <- floor(Count / 2)
仅单指标越界：  Count 保持不变，同时继续动态降权
```

`Count` 保持为非负整数，例如 `1 -> 0`、`3 -> 1`、`5 -> 2`；阈值判断仍为 `Count >= C_tol`。内部状态继续沿用历史属性名 `consecutive_suspicions` 以减少无关改动，但其语义已经是带整数半衰减的异常证据计数，不再是严格的连续轮数。

该规则能避免一次正常判定彻底抹除历史异常，但对旧实验第 49/50 轮的直接反事实结果是：

```text
第48轮后：Count = 1
第49轮正常：Count = floor(1 / 2) = 0
第50轮双指标异常：Count = 1
```

因此，向下取整后，这条具体路径与旧版“正常即清零”的结果相同，并不会保留 `Count=1` 的单次证据；只有正常轮开始时 `Count>=2`，半衰减才会保留部分历史证据。是否改善完整准确率曲线必须重新训练验证。

## 9. 配置级并行和实时进度

此前并行看似无效有两个直接原因：`--jobs` 默认值为 `1`，且 `resolve_parallel_jobs` 在检测到 CUDA/MPS 时无条件返回 `1`。当前已改为：

- `--jobs` 默认 `auto`，示例 JSON 也使用 `"jobs": "auto"`；
- CPU/NumPy 配置使用 `ProcessPoolExecutor`，任务网格中的配置由固定 worker 队列领取；进程池因环境 semaphore 权限不可用时回退线程池；
- CUDA/MPS 配置使用同一进程内的 `ThreadPoolExecutor`，共享设备和驻留数据集，避免 GPU 子进程初始化问题；`auto` 默认最多并发 `2`，显式 `--jobs N` 可提高；
- `torch_backend` 的驻留数据集缓存增加锁，防止多个加速器配置首次启动时重复上传同一数据集；
- 启动时明确输出 `experiment_jobs=N` 和 `experiment_executor=serial|process|thread`。

进度条新增独立 daemon 刷新线程。交互式 TTY 每 `1` 秒重绘，即使没有配置完成，`elapsed` 也会变化；首个配置完成并建立吞吐估计后，`eta` 每秒倒计时。非 TTY 日志仍只在状态事件时输出，避免重定向文件每秒增加一行。

真实合成烟测使用 `4` 个配置和 `--jobs 2`，成功解析为 `experiment_jobs=2`、`experiment_executor=process`。受限 Codex 沙箱中由于系统进程 semaphore 被禁止，会触发预期的 `process_pool_unavailable` 并回退到双线程；在正常系统权限下重复同一烟测时，CPU 进程池未回退且 4 个配置全部完成，总墙钟时间约 `0.29s`。
