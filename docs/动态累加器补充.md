# SM9-RRS-FL v2 任务环签名与门限追踪说明

本文档对应最新版方案第 4.3.1—4.3.4 节。旧版 `(h,R,S,T) + SM9 IBE 撤销陷门` 已停用；当前协议不携带加密身份陷门，也没有独立的非交互式零知识证明对象。

## 系统与任务材料

设双线性群 `G1、G2、GT` 的阶为素数 `N`，生成元为 `P1、P2`。对客户端身份定义：

```text
v_i = H1(ID_i || hid, N)。
```

D-KGC 以 `(t,n)` 门限方式维护互相独立的 SM9 主密钥 `msk`、追踪秘密 `ξ` 和门限 Schnorr 追踪证书密钥 `tsk`。系统只公开：

```text
mpk = [msk]P2，
S_tr = [ξ]P2，
L_ξ = {P1, [ξ]P1, ..., [ξ^q]P1}。
```

此外公开门限 Schnorr 验证密钥：

```text
TPK = [tsk]P2。
```

任务 `TaskID` 使用秘密随机数 `κ_t` 生成：

```text
h_t = H_G2(TaskID || κ_t)。
```

`h_t` 只安全分发给合法客户端、AS 和 D-KGC，不写入上传数据包。客户端签名私钥为：

```text
dS_i = [msk / (msk + v_i)]P1。
```

## 固定任务环与成员见证

对有序任务环 `R = (ID_1, ..., ID_m)`，计算：

```text
RID = H3(R)，
ACC_R = [∏(v_i + ξ)]P1，
W_i = [∏_{j≠i}(v_j + ξ)]P1。
```

成员见证满足：

```text
e(W_i, [v_i]P2 + S_tr) = e(ACC_R, P2)。
```

任务材料同时预计算：

```text
g1 = e(P1, mpk) · e(ACC_R, P2)，
g2_i = e(W_i + dS_i, P2)，
Tag_i = e(dS_i, h_t)。
```

`Tag_i` 是任务内稳定、跨任务变化的匿名标签。AS 以其摘要作为纵向检测和动态权重的索引，但不能仅由标签恢复身份。

## 签名生成

客户端 `ID_π` 对第 `r` 轮模型更新 `G` 构造：

```text
M = TaskID || r || H3(G) || RID || ACC_R。
```

随机选择 `r1,r2 ∈ [1,N-1]`，计算：

```text
Ω = g1^r1 · g2_π^r2，
R_tag = Tag_π^r1，
c = H2(RID || M || Tag_π || R_tag || Ω, N)，
a = r1 - c mod N。
```

若 `a = 0`，重新选择随机数；否则计算：

```text
A = [a]W_π，
B = [a]dS_π，
C = [r2 · a^(-1) + v_π]P2。
```

上传数据包为：

```text
(TaskID, r, G, RID, ACC_R, Tag_π, R_tag, σ)，
σ = (c,A,B,C)。
```

因此，环签名元数据不随任务环成员数量增长。

## AS 验证

AS 根据 `TaskID、r、G、RID、ACC_R` 重构 `M`，并计算：

```text
Ω' = e(A, S_tr + C) · e(B, mpk + C) · g1^c。
```

只有以下两个等式同时成立，数据包才合法：

```text
c = H2(RID || M || Tag_π || R_tag || Ω', N)，
R_tag = e(B, h_t) · Tag_π^c。
```

第一个等式验证任务环成员资格、SM9 私钥映射和消息完整性；第二个等式把未公开的 `h_t`、同一客户端私钥和任务标签绑定到同一份签名。Auditor 可在不知道 `h_t` 的情况下复核第一个等式，但 AS 必须验证两个等式。

## 门限追踪与撤销

当同一 `Tag_π` 连续发生奇异值变化与方向变化两个 Z-Score 共同越界并达到 `C_tol` 时，AS 立即拒绝该触发轮梯度，保存完整证据 `E_π`，并请求 Auditor/D-KGC 追踪。单指标越界仅触发疑似标记与动态降权，不增加连续计数。AS 还使用独立控制面 Schnorr 密钥为精确的 `TaskID、RID、H5(E_π)` 生成提交票据；该票据只实现认证信道，不进入 `E_π` 或 `H5(E_π)`。

追踪不能由调用者提交若干节点编号直接启动。Auditor 为本次证据生成一次性会话标识 `sid`，构造：

```text
Req_trace = TaskID || RID || H5(E_π) || sid。
```

每个参与节点先验证 AS 提交票据，再使用自己的门限证书密钥份额对 `Req_trace` 生成一份独立、可公开验证的 Schnorr 批准。批准同时绑定节点身份、请求内容和节点承诺；重复节点、改名后的批准、属于另一证据或另一会话的批准均无效。D-KGC 只有在验证不少于 `t` 个不同节点的有效批准后，才创建一次性追踪会话。会话同时绑定本次证据中的 `A、B、Tag_π` 以及任务点 `h_t`，并强制按“候选匹配→标签重建→固定消息签证”的顺序执行，不能被复用为任意标签或任意消息签名接口。会话使用后立即关闭，请求摘要写入防重放台账并随检查点保存。

随后，对环中每个候选身份 `ID_j`，D-KGC 使用私有系数：

```text
Δ_j = (v_j + ξ) · (∏(v_i + ξ))^(-1)。
```

计算并比较：

```text
X_j = e(B, [v_j]P2 + mpk)，
Y_j = e([Δ_j]A, mpk)。
```

唯一满足 `X_j = Y_j` 的候选身份记为 `ID_j`。随后由不少于 `t` 个 D-KGC 节点分别计算部分任务标签并通过拉格朗日系数组合出候选标签 `Tag_j*`；完整 `β_j` 和 `dS_j` 均不输出。最终要求：

```text
Tag_j* = Tag_π。
```

D-KGC 最后将下列字段按定长、带长度前缀的规范编码组成追踪消息 `M_trace`：

```text
H5(E_π) || ID_j || Tag_π || RID || "trace"。
```

不少于 `t` 个节点使用独立的门限 Schnorr 份额生成证书。设参与集合为 `S`，节点随机数为 `k_i`，对应拉格朗日系数为 `λ_i`，则：

```text
R_trace = Σ_{i∈S} [k_i]P2，
e_trace = H2("SM9-RRS-FL/threshold-schnorr/v2" || M_trace || R_trace, N)，
z_trace = Σ_{i∈S}(k_i + e_trace · λ_i · tsk_i) mod N，
τ_trace = (R_trace, z_trace)。
```

AS 使用公开 `TPK` 验证：

```text
[z_trace]P2 = R_trace + [e_trace]TPK。
```

挑战值同时绑定消息和承诺，因此不能把旧式单群元证书按同一标量缩放后用于伪造。

AS 创建 `E_π` 时会把完整不可变证据、摘要和提交票据登记为待审计项。仅验证追踪结果不会关闭该记录；只有证据绑定、身份/标签/RID 一致且 `TVrfy` 通过，并且完整证据与认证结果已显式归档后，AS 才关闭待审计项、把 `ID_j` 加入黑名单，并重建任务环的 `RID、ACC、W、g1、g2`。追踪临时失败时，检查点保留完整证据供重启后优先重试，触发轮梯度仍保持拒绝。归档记录随检查点保存，在任务秘密销毁后仍可供审计。旧 `RID` 只保留用于历史审计，不能继续产生或接受当前轮签名；若撤销后没有剩余环成员，任务直接终结而不复用旧环。任务仍有任一待审计项时，`finalize_task` 必须拒绝销毁 `κ_t` 和 `h_t`；该状态在检查点恢复后仍然有效。

## 与代码实现的对应关系

- `sm9rrsfl/threshold.py`：Shamir/Feldman 份额、门限授权、任务环私有材料、候选标签部分结果组合和门限 Schnorr 追踪证书。
- `sm9rrsfl/crypto.py`：`σ=(c,A,B,C)`、两个验签等式、证据封装、追踪和环更新。
- `sm9rrsfl/accumulator.py`：动态累加器基础代数与见证测试。
- `sm9rrsfl/fl.py`：以任务标签驱动检测和降权，仅在追踪证书验证成功后撤销身份。
- `sm9rrsfl/sm9_backend.py` 与 `_native_sm9.c`：国标 SM9 的 65 字节 `G1`、129 字节 `G2`、384 字节 `GT` 规范编码、子群校验、配对和直接 `H_v`。

`crypto_mode="simulated"` 只保留同构标量代数，供快速实验自检；`crypto_mode="sm9"` 必须使用 `gmssl-sm9-native-v2` 原生桥，不存在静默回退到其他曲线的路径。旧 `_native_rrs.c` 属于 v1 源码，不参与 v2 构建或运行。

## 实验实现与生产 D-KGC 的边界

当前代码真实执行 Shamir 份额生成、Feldman 关系检查、拉格朗日组合、份额域交叉项乘法、随机盲化求逆、SM9 群运算、逐节点追踪批准以及门限 Schnorr 验证。环建立利用公开 `L_ξ` 计算 `ACC/W`；`Δ_j` 与 `β_j` 始终以刷新后的 Shamir 份额存在，求逆阶段只重构均匀随机掩码保护的乘积。因此 `msk`、`ξ`、`P_r`、`P_r^(-1)`、`β_j`、客户端私钥标量和 `Δ_j` 均不会在环建立或追踪路径中恢复为完整标量。

客户端与 AS 使用单向下发的专用状态：客户端仅持自己的私钥和见证；AS 持验签参数、非公开任务点、TPK、独立的审计提交认证密钥和审计台账，其对象图不含追踪网关或 D-KGC 份额。Paillier 加密报文、认证信道和独立主机并未在本仓库中部署；控制面票据只模拟认证后的提交来源。单进程实验编排层仍可访问各节点对象并统一保存检查点，同进程调试器、`gc` 遍历和内存读取也不属于安全边界。因此，本实现适合验证方案等式、份额域数据流、门限调用条件、追踪证据绑定和联邦学习效果，但不应当作为生产环境中的跨信任域密钥存储或通信方案。原生 GmSSL z256 运算尚未声明为恒定时间，生产部署还需要独立节点、认证信道、可擦除密钥库和侧信道加固。
