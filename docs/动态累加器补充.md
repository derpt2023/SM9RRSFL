# SM9-RRS-FL 动态累加器与常数大小环签名补充

建议插入位置：方案文档中介绍可撤销/可追踪环签名流程的小节，放在“系统初始化”之后、“签名生成与验签”之前。若原文已有环成员哈希承诺，可将其替换为本节的动态累加器描述。

## 数学表达

设系统使用 SM9 的双线性群 `G1, G2, GT`，阶为素数 `N`，生成元分别为 `P1, P2`。对客户端身份 `ID_i` 定义：

```text
v_i = H1(ID_i || hid, N)。
```

累加器构造者选择秘密参数：

```text
s ∈ [1, N-1],
```

并公开：

```text
S_pub = [s]P2,
L = {P1, [s]P1, [s^2]P1, ..., [s^q]P1},
```

其中 `q` 为可累加的最大环成员数量。对当前联邦学习任务中的公共环：

```text
U = {ID_1, ID_2, ..., ID_n}, n ≤ q,
```

累加器值为：

```text
V = [ ∏_{i=1}^{n}(v_i+s) ] P1。
```

签名者 `ID_π` 的成员见证为：

```text
W_π = [ ∏_{i=1,i≠π}^{n}(v_i+s) ] P1。
```

聚合服务器或签名者可通过以下等式验证见证有效性：

```text
e(W_π, [v_π]P2 + S_pub) = e(V, P2)。
```

因此，签名数据中无需携带完整环成员列表，只需在任务上下文中绑定公共环摘要和累加器值摘要。环成员数量增加时，签名数据仍保持常数级。

## 签名与验签

设 SM9 签名主公钥为：

```text
P_pub-s = [k_s]P2,
```

客户端 `ID_π` 的 SM9 签名私钥为：

```text
ds_π = [ k_s / (v_π + k_s) ] P1。
```

签名时先计算：

```text
g1 = e(P1, P_pub-s) · e(V, P2),
g2 = e(W_π + ds_π, P2)。
```

随机选择 `r1, r2 ∈ [1,N-1]`，计算：

```text
ω = g1^r1 · g2^r2,
h = H2(U || M || ω, N),
R = [r1-h]W_π,
S = [r1-h]ds_π,
T = [ r2(r1-h)^(-1) + v_π ]P2。
```

输出常数大小签名：

```text
σ = (h, R, S, T)。
```

验签时，验证者根据任务公共环得到 `V` 和 `g1`，然后计算：

```text
ω' = e(R, S_pub + T) · e(S, P_pub-s + T) · g1^h,
h' = H2(U || M || ω', N)。
```

若：

```text
h' = h,
```

则验签通过。

## 与代码实现的对应关系

- `sm9rrsfl/accumulator.py`：实现 `V`、`W_π`、动态添加、动态删除和成员见证验证。
- `sm9rrsfl/crypto.py`：默认 `accumulator_mode="dynamic"`，真实 SM9 模式下生成 `σ=(h,R,S,T)`，验证过程不依赖完整环成员列表。
- `RRSPacket.ring`：动态累加器模式下为空元组，避免签名包大小随环成员数量线性增加。
- `RRSPacket.ring_size`：记录公共环大小，仅用于实验统计和一致性校验。
- `RRSPacket.ring_accumulator`：记录累加器值摘要，用于绑定公共环状态。

实现中仍保留 SM9 加密撤销陷门，以兼容原 SM9-RRS-FL 的审计追溯流程：检测确认恶意后，审计方解密陷门得到真实客户端身份；动态累加器主要负责压缩环签名数据并使签名/验签不再线性依赖环成员列表。
